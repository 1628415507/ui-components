# LangChain 语法梳理技能 (LangChain Syntax Curator)

## 核心任务
从 LangChain 源码或实战代码中提取核心组件 (Models, Prompts, Parsers, LCEL, Chains) 的用法，并同步到 `docs/LangChain.md`。

## 执行流程
1. **深度分析**：
    - 识别模型接口、Prompt 模板、OutputParser 及 LCEL 管道逻辑。
    - 提取 Runnable 接口调用（`invoke`, `stream`, `batch`）及多轮对话管理。
2. **分类同步**：
    - 将提取的知识点按模块（Models, Prompts, Chains 等）更新至 `docs/LangChain.md`。
    - 重点记录代码解决的特定问题及实现逻辑。

## 梳理规范

### 内容与结构
- **精准去重**：表述简洁准确，禁止语义相近的句子重复出现。
- **合并梳理**：待补充内容与已有知识点属同一属性或主题时，在原条目下合并补充，禁止另起新条目；保持结构单一、信息集中。
- **模块化组织**：严格遵循 LangChain 官方核心组件结构更新文档。
- **属性表格化**：类、方法、配置对象的**属性 / 参数 / 键**优先用 Markdown 表格呈现（如「参数 \| 作用」「键 \| 含义 \| 默认值」），避免多级无序列表逐条罗列；表格不足以表达时，再在表格下方用简短段落补充。
- **通用先行**：同一主题下多个具体实现共用的属性、方法、接口，须先整理为「通用」小节（置于各实现小节**之前**）；具体实现小节只记录初始化差异与增量能力，禁止在末尾重复汇总通用内容。

### 交叉引用

文档内已有相关知识点时，**优先在正文出现处直接加链接**，避免另起引用块重复指向。

#### 行内链接（优先）

- **适用场景**：当前句或表格单元格中提到了已在**前文**记录过的属性、方法、组件或接口（如 `add_texts`、`similarity_search`、`ChatPromptTemplate`），仅需跳转查阅、不在此展开。
- **写法**：在**该名称首次出现处**用 Markdown 链接包裹，链接文字即 API / 组件名本身，锚点指向已有说明所在小节。

  ```markdown
  | **1. 写入资料** | [`add_texts(list[str])`](#101-通用-api) 或 [`add_documents`](#101-通用-api) 向向量库添加参考文本 |
  | **2. 检索匹配** | [`similarity_search(查询文本, k)`](#101-通用-api) 取与问题最相关的文档 |
  ```

  ```markdown
  向量存储实例除 [`add_documents`](#101-通用-api) 外，可用 [`add_texts(list[str])`](#101-通用-api) 直接传入字符串列表。
  ```

- **链接格式**：须含章节编号与锚点；链接文字与文中实际提及的名称一致，禁止空链接（如 `[add_texts(list[str])]()`）。
- **禁止重复**：同一小节内已对某 API 加了行内链接后，**不再**用引用块或段落重复「见 §x.x」。

#### 引用块（补充说明时）

仅当需要**附加说明性文字**（解释为何不在此展开、或指向整节背景知识而非单个 API）时，才用 Markdown 引用块（`>`），与正文区分。

- **添加前提**：当前小节正文已涉及该主题，仅为避免重复展开才添加；小节完全不涉及该主题时（如 §1.2 仅介绍模型初始化），禁止添加无关引用。
- **链接格式**：须含章节编号与锚点；同一引用块内多行时，每行均以 `>` 开头。

  ```markdown
  > 本节解释 [5.1](#51-管道语法-) 中 `|` 的底层实现，用法本身见上文，此处不再重复。

  > `load()` / `lazy_load()` 用法同 [8.1 通用特性](#81-通用特性-baseloader)。
  ```

- **与行内链接的分工**：单个 API / 属性 / 参数 → 行内链接；整节原理、通用约定、或代码块内不便加链的省略说明 → 引用块。

### 范围与补全
- **范围限制**：仅梳理用户指定的文件，严禁引入无关代码。
- **全量补全**：示例中出现文档未涵盖的新方法（如 `to_string()`、`save()`）时，须同步补充其功能与用法。

### 代码块
- **示例来源**：代码块中的示例**优先**取自待梳理范围内的 Python 实战文件（如 `03-LangChain/*.py`）；须从源文件提取或截取相关片段，保持 import、变量名、参数与注释一致，禁止凭空编写与项目代码风格或 API 用法不一致的示例。源文件无对应片段时，方可按 LangChain 官方用法最小补全，并注明来源。
- **关键片段**：只截取与本节知识点直接相关的代码段，**禁止整文件搬入**。可省略：与本节无关的 import、路径常量、已在其他章节展开的 loader / 写入 / 删除逻辑，以及源文件中已注释掉的重复代码；改用 [行内链接](#行内链接优先) 或 [引用块](#引用块补充说明时) 指向已有章节。同一 API 仅在首次出现的小节给出完整示例，后续小节只展示增量差异（如 Chroma 的 `filter` 参数）。
- **保留注释**：截取片段内已有的注释须原样保留（含行内 `#` 与步骤说明）；仅当注释错误或已与代码不符时才可修正。省略整段无关代码时，不得将其以注释形式保留在示例中。
