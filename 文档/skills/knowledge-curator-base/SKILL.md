# 知识点梳理通用规范 (Knowledge Curator Base)

本文件定义「从源码/配置提取知识点并写入 `文档/*.md`」类技能的**共享规范**。具体领域技能须先遵循本规范，再叠加各自的分析范围与目标文档。

## 内容与结构

- **精准去重与结构互联**：
    - 表述简洁准确，禁止语义相近的句子或内容重复出现。
    - **禁止表格定义重复**：当前面的「核心汇总」表格已定义基础属性（如名称、作用、应用场景、示例）时，后续专题章节**严禁**用相同或相似表格再次罗列这些基础属性。
    - **优雅去重手段**：
        1. 子章节若仅说明概念角色，用纯文本描述，并用 Markdown 行内链接（如 `[组件](#锚点)`）指回汇总表。
        2. 若需展开机制、原理、生命周期等，用正文、流程图或关键代码/配置片段深入说明，禁止在子表格中重复基础释义。
    - **维护锚点一致性**：调整章节标题时，必须同步核对并更新文档内所有 Markdown 锚点链接，禁止死链。
- **合并梳理**：待补充内容与已有知识点属同一属性或主题时，在原条目下合并补充，禁止另起新条目；保持结构单一、信息集中。
- **模块化组织**：按该领域知识体系结构更新文档（具体大纲由领域技能给出）。
- **属性表格化**：关键字、注解、配置项、方法参数、节点属性等优先用 Markdown 表格呈现（如「名称 | 作用 | 示例」），避免多级无序列表逐条罗列。
- **通用先行**：同一主题下多个具体实现共用的属性、方法、接口或规则，须先整理为「通用」小节（置于各具体实现小节**之前**）。

## 交叉引用

文档内（或与其它 `文档/*.md`）已有相关知识点时，**优先在正文出现处直接加链接**。

- **行内链接（优先）**：在名称首次出现处用 Markdown 链接包裹，锚点指向已有说明所在小节。
- **引用块（补充说明时）**：仅当需要附加说明性文字时使用。

## 范围与限制

- **范围限制**：只能从用户给定（或领域技能明确指定）的源码/配置中梳理知识点，严禁自造无依据的内容。
- **禁止修改代码**：**严禁修改任何源码与配置文件**；核心任务是“提取”与“梳理”知识并更新至文档。
- **个人信息 / JavaDoc**：
    - 写入 `文档/*.md` 的示例中，**严禁**包含 `@author` 等个人信息，保持文档简洁。
    - 在其他场景（如生成新的 Java 源码文件）下，必须遵循项目规范，在所有类和方法的 JavaDoc 中包含 `@author majf`。

## 代码与配置块

- **示例来源**：代码/配置/命令示例**优先**取自项目内实战文件（具体路径由领域技能给出）。
- **关键片段**：只截取与本节知识点直接相关的片段，**禁止整文件搬入**。
- **保留注释**：截取片段内已有的注释（含 JavaDoc、行内注释以及 xml/yml 中的注释）须原样保留。
