# Java 知识点梳理技能 (Java Knowledge Curator)

## 核心任务
从 Java 源码中提取核心知识点（如关键字用法、面向对象特性、集合框架、多线程、JVM 配置等），并同步到 `文档/JAVA.md`。

## 执行流程
1. **深度分析**：
    - 识别 Java 关键字（如 `package`, `public`, `static`, `final` 等）及其应用场景。
    - 提取类结构、继承关系、接口实现及常用设计模式。
    - 分析常用 API（如 `java.util`, `java.io`, `java.nio` 等）的调用逻辑。
2. **分类同步**：
    - 将提取的知识点按模块（环境配置、关键字、面向对象、集合等）更新至 `文档/JAVA.md`。
    - 重点记录代码解决的特定问题及实现逻辑。

## 梳理规范

### 内容与结构
- **精准去重**：表述简洁准确，禁止语义相近的句子重复出现。
- **合并梳理**：待补充内容与已有知识点属同一属性或主题时，在原条目下合并补充，禁止另起新条目；保持结构单一、信息集中。
- **模块化组织**：遵循 Java 知识体系结构更新文档。
- **属性表格化**：关键字、方法参数、配置项优先用 Markdown 表格呈现（如「关键字 | 作用 | 示例」），避免多级无序列表逐条罗列。
- **通用先行**：同一主题下多个具体实现共用的属性、方法、接口，须先整理为「通用」小节（置于各实现小节**之前**）。

### 交叉引用
文档内已有相关知识点时，**优先在正文出现处直接加链接**。
- **行内链接（优先）**：在名称首次出现处用 Markdown 链接包裹，锚点指向已有说明所在小节。
- **引用块（补充说明时）**：仅当需要附加说明性文字时使用。

### 范围与限制
- **范围限制**：只能从用户给定的 Java 文件中梳理知识点，严禁梳理关联的其他本地文件内容。
- **禁止修改代码**：**严禁修改任何 Java 源码文件**；技能的核心任务是“提取”与“梳理”知识并更新至文档。
- **JavaDoc 规范**：
    - 在提取或生成代码示例到 `文档/JAVA.md` 时，**严禁**包含 `@author` 等个人信息，保持文档简洁。
    - 在其他场景（如生成新的 Java 源码文件）下，必须遵循项目规范，在所有类和方法的 JavaDoc 中包含 `@author majf`。

### 代码块
- **示例来源**：代码块中的示例**优先**取自项目内的 Java 实战文件。
- **关键片段**：只截取与本节知识点直接相关的代码段，**禁止整文件搬入**。
- **保留注释**：截取片段内已有的注释须原样保留（含 JavaDoc 和行内注释）。
