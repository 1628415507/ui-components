# 前端 AI 学习路线：从 Cursor 到 AI 原生工程师 (Product Engineer)

> 本文档由架构师视角整理，旨在帮助前端开发从“AI 使用者”进化为“AI 能力集成者”，并在面试中展现核心竞争力。

---

## 一、 架构师视野：AI 与前端结合的三个阶段

1.  **工具化 (AI for Productivity)**
    *   **目标：** 效率提升 2-5 倍。
    *   **核心：** 深度掌握 Cursor (Composer 模式、`.cursorrules`)。
    *   **实践：** 自动化生成 Unit Tests、E2E 测试和业务逻辑。

2.  **集成化 (AI for Application)**
    *   **目标：** 在现有业务系统中嵌入 AI。
    *   **核心：** **Vercel AI SDK** (推荐)、LangChain.js (进阶)。
    *   **实践：** 智能录入、结构化数据提取、RAG (企业知识库问答)。

3.  **原生化 (AI-Native Frontend)**
    *   **目标：** 以 AI 为核心重新设计 UI/UX。
    *   **核心：** **Generative UI (生成式 UI)**、Edge AI、多模态。
    *   **实践：** 意图驱动交互 (Intent-based UI)，根据 AI 推理结果动态渲染组件。

---

## 二、 零基础快速起步 (面试高含金量路径)

### 第一步：结构化输出 (Structured Outputs) —— 解决稳定性
*   **痛点：** AI 返回的文字无法直接被前端解析。
*   **学习：** Zod 库定义 Schema，配合 LLM 的 `JSON Mode` 或 `Function Calling`。
*   **面试加分：** “我通过控制输出的确定性，确保了 AI 与前端组件库的无缝对接。”

### 第二步：流式渲染 (Streaming) —— 优化用户体验
*   **痛点：** AI 响应慢，用户白屏等待。
*   **学习：** Vercel AI SDK 的 `useChat`、`ReadableStream` 处理。
*   **面试加分：** “我深入优化了 AI 生成的首字节时间 (TTFB)，实现了平滑的流式输出交互。”

### 第三步：提示词架构 (Prompt Engineering) —— 解决业务深度
*   **痛点：** AI 容易产生幻觉，逻辑不严密。
*   **学习：** Few-shot (少样本学习)、CoT (思维链)、提示词注入防御。
*   **面试加分：** “我将复杂的业务规则通过提示词工程进行了建模，并实现了前端的安全防护。”

### 第四步：Generative UI (生成式 UI) —— 最前沿竞争力
*   **痛点：** 对话框交互单一。
*   **学习：** 让 AI 根据上下文直接调用前端组件（如 `streamUI`）。
*   **面试加分：** “我实现了一套组件动态下发方案，让系统能根据用户意图实时生成对应的图表或表单。”

---

## 三、 进阶补充：LangChain.js

**什么时候学？**
当你需要处理复杂的 AI 工作流（Chains）、需要管理长期记忆（Memory）或构建自主决策的机器人（Agents）时。

**学完能做什么？**
*   **增强型 RAG：** 让 AI 学习企业私有文档。
*   **智能 Agents：** 让 AI 自动执行任务（如：查延误航班并自动发邮件）。
*   **自动化链：** 串联多个 AI 任务（总结 -> 翻译 -> 检查 -> 发送）。

## 四、 面试架构师视角话术 (Architect Level)

1.  **谈性能与成本：** “我会通过上下文截断和 Prompt 精简来控制 Token 成本，节省 API 开支。”
2.  **谈鲁棒性：** “我建立了 AI 失败的 Fallback 降级机制，确保在 API 挂掉时系统依然可用。”
3.  **谈交互演进：** “我认为 AI 的终极形态不是聊天框，而是无感知的辅助，如‘智能预填充’和‘实时校验’。”

## 五、 推荐练习项目

**“智能订单/表格助手”**
1.  **前端：** Next.js + Tanstack Table。
2.  **后端：** Vercel AI SDK + DeepSeek/OpenAI API。
